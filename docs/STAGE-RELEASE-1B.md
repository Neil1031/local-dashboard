## Overview source and meaning

| Display | Existing source / calculation | Boundary |
| --- | --- | --- |
| Monitored | Entire validated `/api/jobs` snapshot, `jobs.length` | Independent of Today filters, legacy folding and metadata hidden. PARTIAL covers only collected jobs. |
| Attention | Current FAILED / UNKNOWN / explicit MISSED statuses through existing `summarize` | No new MISSED inference; READY does not mean ran today. Collection diagnostics remain separate. |
| Failed / successful last result | Existing `lastRunStatus` | Scheduler result, not application business success or today's result. |
| Upcoming | Enabled collected jobs with valid future `nextRunAt`, ascending time, at most five | Scheduler-supplied time, not a guarantee of execution; no past time presented as upcoming. |
| Recent observed | Existing seven-local-calendar-day `/api/history`, latest five nonfuture observed runs | Original stored identities/outcomes; full fractional UTC precision, then run ID. Empty history does not imply MISSED. |
| Runner | Shared `/api/runner/executions` snapshot, exact full task mapping and existing coverage states/warnings | Receipt diagnostics, not execution inference or source health. Missing/unconfigured/error stays unavailable. |

Refresh clears old summaries and the History cache before collecting new jobs. History request revisions reject late successes and failures from an older refresh. History errors expose a bounded reason and retry. History/Runner completion retains unchanged Upcoming buttons so Escape can return focus after opening a drawer while another read is pending. Settings saves update labels and cached views without recollecting jobs; revision conflicts, dependency validation and resets keep the existing implementation.
