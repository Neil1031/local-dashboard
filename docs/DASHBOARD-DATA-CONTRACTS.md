# Local Dashboard — Data Contracts and Source Mapping

Design proposal, version `dashboard-domain-v1`; not an implemented API. Cross-source identity and provenance are mandatory. A field marked nullable must remain `null`/— when not observed; zero means an actual measured zero. `observedAt` is when the adapter saw data, while source event time, filing time, report date, run time and data-effective date are distinct.

## Shared response contract

Each future collection response uses `{contractVersion, dataState, items, page:{limit,offset,hasMore}, observedAt, sources:[{sourceId,sourceVersion,lastObservedAt,warning}], warnings}`. Detail responses retain `dataState`, `observedAt`, `sources`, `warnings` and one `item`. Supported state vocabulary: `LOADING` (client only), `READY`, `EMPTY`, `PARTIAL`, `STALE`, `UNAVAILABLE`, `ERROR`. Source-specific flags remain separate: a quality warning is not a transport error; an observed failed job is not missing execution. Unsupported contract versions fail closed with `UNAVAILABLE`, never silently map unknown fields.

The models below list **required** core fields; `null` in optional fields indicates unavailable/not observed, not a negative assertion. Version fields describe the source contract/snapshot, not a promise that historical state is complete.

| Model | Identity and required fields | Optional fields and null semantics | Provenance and version |
| --- | --- | --- | --- |
| `AutomationJob` | Canonical full Dashboard job ID, displayName, enabled, schedulerStatus, observedAt | nextRunAt/lastRunAt may be null if Scheduler lacks them; market/group/description are display metadata | raw Scheduler task path, collector observation, job metadata revision; never substitute Runner native ID |
| `ExecutionEvidence` | evidenceId, canonicalJobId if trusted, sourceKind (`SCHEDULER`/`RUNNER`), observedAt, outcome | startedAt/completedAt/exitCode/receipt path and nativeJobId nullable; unmatched evidence may have no canonical ID | immutable source identity, receipt/collector version and trust mapping; failed execution remains executed failure |
| `ScheduleVersion` | canonical full task path, scheduleVersion, firstObservedAt, lastObservedAt, normalized triggers, timezone, enabled | previousVersion/changeGap nullable; gap means visibility uncertainty | Stage A snapshot identity, source observation and normalization version |
| `OccurrenceCorrelation` | correlationId, canonicalJobId, scheduleVersion if supported, state, candidate schedule time, evidence refs | selectedOccurrenceAt null for ambiguous/unsupported; reason and competing candidates retained | Stage B shadow policy/version and Scheduler/Runner refs; research tolerance is not Windows provenance |
| `Signal` | source-scoped signalId, sourceKind, ticker, eventDate, discoveredAt, discoveredBasis, active/review state | company, scores with origin/breakdown, buyerCount/amount, reportDate, performance refs nullable; report and SEC signals do not magically share identity | Insider normalized contract v1 or future TW export; source refs and quality flags |
| `Transaction` | source-scoped transactionId, ticker, insider, transactionDate, transactionCode, filingDate, source document ref | issuer, shares/price/amount, form/amendment, owner role, acceptedAt, source URL, review flags nullable | SEC accession + transaction index; reconciliation state explicit; source record version |
| `Report` | source-scoped reportId, reportType, reportDate, sourceRef, import/processing state | raw Markdown, parsed signal count, warnings, revision list/diff nullable; unknown revision comparison stays absent | source file/artifact/hash, importedAt, report revision/hash, adapter version |
| `Performance` | source-scoped signalId, horizon, asOf, observationStatus (`OBSERVED`/`PARTIAL`/`PENDING`), source basis | entry/exit price, return, win flag, upside/adverse/drawdown, daysToPeak/first10Gain/first10Loss all nullable until observed | price provider/session basis, snapshot time and methodology version; never use 0 for pending |
| `DataSourceHealth` | sourceId, availability, readOnly, observedAt, dataState | schema/contract version, lastDataAt, expectedRefresh, freshnessState, warning, path label nullable; success does not prove completeness | check method and time, source contract/schema version, coverage metadata |

All timestamps use ISO 8601 with offsets or explicit timezone. Dates without times stay dates. Monetary amounts have currency and source basis; no exchange-rate conversion is implicit. Scores keep source scale/origin. The UI may sort/filter but cannot derive missing scores, buyer counts, outcomes or freshness from unrelated tables.

## Freshness and evidence rules

`DataSourceHealth` records both last successful **observation** and latest **data-effective** time. An expected-refresh policy is source-specific and time-zone aware; no universal daily cutoff is assumed. `FRESH`, `STALE`, `UNKNOWN`, `UNAVAILABLE` are freshness/availability assessments separate from `dataState`. An executed Scheduler task can coexist with partial or stale source data. Every freshness verdict must carry the threshold/policy version and latest observation; unsupported/missing policies produce `UNKNOWN`.

Stage B occurrence data is shadow diagnostic evidence. Current research parameters (early 2 minutes, ordinary late 5 minutes, possible catch-up 3 hours, Scheduler/Runner merge 30 seconds) do not establish Windows Scheduler provenance. Schedule-version gaps take precedence as `AMBIGUOUS_SCHEDULE_VERSION`; relevant unsupported episodes remain `UNSUPPORTED`; multiple triggers can be ambiguous; failed execution remains an executed failure. Missing evidence cannot generate production `MISSED` until Release 4's availability/provenance and false-positive gate.

## Project Design v1 build snapshot

Release 1A-1 implements this narrow contract independently of the future domain APIs above. Sole source: `docs/PROJECT-DESIGN.md`; Maven copies only this named file to `static/project-design/PROJECT-DESIGN.md`. The production browser GETs the fixed same-origin resource with `cache: no-store`, `mode: same-origin`, `redirect: error`. There is no arbitrary path/URL input, source repository scan, shell invocation or DB access.

`ui/project-design.mjs` is the shared browser-compatible pure parser used by production and `design/prototype/generate-project-design.mjs`. Required front matter is `project_id`, `project_name`, `repository`, `design_version`, `overall_status`, `baseline_commit`, `last_reviewed_at`, `purpose`, `original_design`, `current_design`. Supported `design_version` is integer 1; later positive integers return `UNSUPPORTED_VERSION`. Invalid metadata/real dates, duplicate feature IDs, unknown status, empty required cells, changed columns or malformed required tables return `INVALID_FORMAT`. The v1 table format is a single contiguous pipe table per required heading, with literal pipe delimiters; escaped pipes/multiline cells are not supported. Required tables: Feature Matrix, Major Development Issues & Lessons, Design Changes, Remaining Work.

Parsed fields: `metadata`, `features[{id,area,name,originalIntent,implementation,status,limitation,remaining,evidence}]`, `issues`, `changes`, `remaining`. The feature status vocabulary remains DONE/PARTIAL/BACKEND_READY/DATA_READY/DESIGNED/IN_PROGRESS/NOT_STARTED/DEFERRED/BLOCKED/DROPPED. Counts are derived from features, including zero counts. Production additionally accepts only `project_id: local-dashboard` and `repository: Neil1031/local-dashboard`. No hard-coded production inventory or second status ledger exists.

The loader caps raw UTF-8 bytes at 256 KiB (including streaming responses), rejects invalid UTF-8 and HTML error pages, and bounds a read to 10 seconds. 404 -> MISSING; invalid data -> INVALID_FORMAT; unsupported version -> UNSUPPORTED_VERSION; size -> TOO_LARGE; network/timeout/other HTTP failures -> UNAVAILABLE. The UI clears prior rows/counts/provenance at each reload, retains only the newest request result, gives safe localized messages and retry, and renders values with `textContent`. Raw error bodies/private paths are not displayed.

Provenance is `{model,digest,readAt}`: SHA-256 over exact served bytes, browser read time, source-relative path, source repository and design metadata. `baseline_commit`/`last_reviewed_at` remain historical inventory metadata, not current implementation SHA or a fresh test. The resource is a build snapshot until a new build; browser reload cannot incorporate an unbuilt Git edit. The generated `window.PROJECT_DESIGN_SAMPLE` remains only a static prototype artifact and is never imported by production. Full Projects/aggregation and other releases remain pending.
